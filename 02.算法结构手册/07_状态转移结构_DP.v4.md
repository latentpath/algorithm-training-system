# 第七章：状态转移结构（DP）

> 核心信念：**DP 不是记忆公式，而是在重叠子问题中定义状态、维护依赖并完成转移。**

---

# ① 本章解决什么结构问题？

本章解决的是：

> 当问题可以被拆成阶段，并且不同决策路径会反复到达相同子问题时，如何用状态表达历史影响，并通过状态转移完成求解。

DP 的本质不是：

```text
最长
最短
方案数
```

而是：

```text
当前状态 = 若干更小状态的组合结果
```

真正重要的是：

- 状态表示什么
- 状态如何承载历史影响
- 状态之间如何转移
- 为什么这些状态已经足够
- 为什么遍历顺序不会破坏依赖关系

---

# ② 本章定位：专题之后，看结构

建议学习顺序：

```text
先学专题：
线性DP → 二维DP → 背包DP → 序列DP → 状态机DP → 区间DP → 树形DP

再看结构：
把不同专题重新归纳为“状态依赖结构”
```

专题手册回答：

> 这种题通常怎么做？

结构手册回答：

> 为什么这些看起来不同的题，本质上共享同一种依赖结构？

因此，本章不按题型模板组织，而是按依赖关系组织。

---

# ③ DP 的统一结构视角

传统分类：

```text
一维DP
二维DP
```

只是“状态数组长什么样”。

真正重要的是：

# 状态依赖结构

因为：

```text
二维数组 ≠ 同一种DP
```

例如：

| 题目 | 本质结构 |
|---|---|
| LCS | 双序列匹配 |
| Edit Distance | 双序列匹配 |
| Unique Paths | 二维有向推进 |
| Minimum Path Sum | 二维有向推进 |
| 区间回文 | 区间合并 |
| 二维背包 | 选择约束 |
| DAG 最长路 | 图依赖结构 |

它们虽然都可能写成：

```text
dp[i][j]
```

但状态依赖关系完全不同。

因此：

> 本章按“状态依赖结构”组织，而不是按数组维度组织。

---

# ④ 状态维度 vs 存储维度

这是理解 DP 的一个关键分界。

## 状态维度

状态本身需要多少变量描述：

```text
dp[i]
dp[i][j]
dp[i][state]
dp[left][right]
```

这属于“建模”。

## 存储维度

实现时到底保存多少历史状态：

```text
完整 dp[]
滚动变量 prev / cur
二维表 dp[][]
滚动数组 dp[]
```

这属于“优化”。

例如：

```text
dp[i] = dp[i - 1] + dp[i - 2]
```

状态逻辑依然是 `dp[i]`。

即使代码最终写成：

```java
int cur = prev1 + prev2;
```

也只是把存储压缩了。

所以：

> **状态定义不能因为空间压缩而消失。**

学习阶段优先写完整状态，再做压缩。

---

# ⑤ DP 的统一建模流程

所有 DP 都遵循：

```text
1. 定义状态
2. 定义状态转移
3. 定义 base case
4. 定义遍历顺序
5. 判断最终答案位置
6. 判断是否可压缩空间
```

统一骨架：

```java
for (state in validOrder) {
    for (choice in choices) {
        dp[state] = combine(
            dp[state],
            dp[previousState]
        );
    }
}
```

核心不变量：

> 当处理当前状态时，它依赖的所有前置状态已经被正确计算。

---

# ⑥ 如何判断状态需要几维？

先问：

> 描述一个子问题，最少需要几个变量？

## 一个变量足够

```text
dp[i]
```

例如：

```text
前 i 个元素的答案
以 i 结尾的答案
到第 i 个位置的答案
```

## 两个变量共同决定

```text
dp[i][j]
```

例如：

```text
网格：row × col
双序列：A前i个 × B前j个
区间：left × right
物品 × 容量
阶段 × 状态
```

注意：

> 二维状态不是一种独立 DP 类型，只是说明一个状态需要两个变量才能完整描述。

---

# ⑦ 状态定义必须足够精确

下面这些状态看起来类似，但语义完全不同：

```text
dp[i] = 前 i 个元素中的最大值
```

和：

```text
dp[i] = 以 i 结尾的最大值
```

第二种会强制“当前状态必须包含 i”。

同样：

```text
dp[i][j] = 到达 (i,j) 的路径数量
```

和：

```text
dp[i][j] = A 前 i 个字符和 B 前 j 个字符的 LCS 长度
```

虽然数组形式相同，但子问题定义完全不同。

因此状态定义必须包含必要限定：

```text
前 i 个
以 i 结尾
必须选 i
到达 (i,j)
最大 / 最小 / 方案数
```

---

# ⑧ 状态依赖结构分类

---

# 1）阶段推进型状态

## 对应专题

- 线性DP
- 二维基础DP
- 状态机DP

## 结构定义

状态沿时间、下标或阶段自然推进。

核心特征：

> 当前状态只依赖更早阶段。

这类结构可以是一维，也可以是二维。

---

## 1.1 单轴推进：线性 DP

典型形式：

```text
dp[i]
```

常见含义：

```text
到第 i 个位置
前 i 个元素
以 i 结尾
```

### 结构信号

| 信号 | 可能结构 |
|---|---|
| 到第 i 个位置 | 线性DP |
| 前 i 个元素 | 线性DP |
| 只依赖前几个位置 | 线性推进 |
| 最大连续子数组 | 线性DP |
| 不能选相邻 | 线性DP / 选择约束 |

### 代码骨架：先显式状态

```java
for (int i = 1; i < n; i++) {
    dp[i] = transition(dp, i);
}
```

### 再做空间压缩

如果：

```text
dp[i] 只依赖 dp[i - 1]
```

可压缩为：

```java
cur = transition(prev);
```

如果：

```text
dp[i] 只依赖 dp[i - 1], dp[i - 2]
```

可压缩为：

```java
cur = transition(prev1, prev2);
```

### 不变量

- 当前状态含义必须稳定
- 转移只能来自历史阶段
- 遍历顺序必须保证依赖已计算
- 空间压缩不能改变状态语义

### 容易误判

| 误判 | 实际结构 |
|---|---|
| 打家劫舍当回溯 | 线性DP |
| 最大子数组当滑动窗口 | 线性DP |
| 只记 prev1/prev2，不会写 dp[i] | 过早空间优化 |

---

## 1.2 二维有向推进：基础二维 DP

这是二维 DP 最基础的一类结构。

典型形式：

```text
dp[i][j]
```

但关键不是“二维”，而是：

> 当前状态依赖固定方向上的更早状态。

例如网格：

```text
(i - 1, j)
(i, j - 1)
    ↓
(i, j)
```

典型题：

- LC62 Unique Paths
- LC63 Unique Paths II
- LC64 Minimum Path Sum

### 统一结构

前驱状态相同：

```text
上方
左方
```

变化的是组合方式：

```text
路径计数：上 + 左
障碍物：非法状态为 0，否则上 + 左
最小路径和：min(上, 左) + 当前代价
最大收益：max(上, 左) + 当前收益
```

### 代码骨架

```java
for (int i = 1; i < row; i++) {
    for (int j = 1; j < col; j++) {
        dp[i][j] = combine(
            dp[i - 1][j],
            dp[i][j - 1]
        );
    }
}
```

### 不变量

- `i`、`j` 的含义必须明确
- 当前状态依赖方向固定
- 第一行 / 第一列通常是边界状态
- 障碍或非法状态可能改变初始化

### 空间压缩

如果当前行只依赖：

```text
上一行同列
当前行左侧
```

二维表可压成一维数组。

但：

> 学习和建模阶段应先写完整二维表。

---

## 1.3 状态机推进

典型形式：

```text
dp[i][state]
```

例如股票：

```text
i = 第几天
state = 持有 / 未持有 / 冷冻期
```

关键区别不是“多写一维数组”，而是：

> 单独知道阶段 i 已经不够，还必须知道当前处于哪种状态。

### 结构信号

| 信号 | 可能结构 |
|---|---|
| 持有 / 未持有 | 状态机DP |
| 今天和昨天有关 | 状态推进 |
| 股票交易 | 状态机DP |
| 阶段相同但历史身份不同 | 状态机DP |

### 推荐骨架：先显式上一阶段

```java
int prevHold = hold;
int prevCash = cash;

hold = Math.max(prevHold, prevCash - prices[i]);
cash = Math.max(prevCash, prevHold + prices[i]);
```

不要在同一轮中让后一个状态错误依赖已经更新后的当前阶段状态。

### 不变量

- 状态身份必须稳定
- 当前阶段应由上一阶段状态转移
- 若原状态为 `dp[i][state]`，空间压缩后仍要保持上一阶段语义

---

# 2）选择约束型状态

## 对应专题

- 背包DP
- 树形DP（部分）

## 结构定义

当前选择会限制未来可选集合。

核心思想：

```text
选 or 不选
```

典型状态：

```text
dp[capacity]
```

或：

```text
dp[node][selected]
```

## 结构信号

| 信号 | 可能结构 |
|---|---|
| 每个元素只能选一次 | 0/1 背包 |
| 元素无限使用 | 完全背包 |
| 容量限制 | 背包 |
| 选当前不能选相邻 | 选择约束 |
| 树上选点 | 树形DP |

## 代码骨架

### 0/1 背包

```java
for (int num : nums) {
    for (int j = target; j >= num; j--) {
        dp[j] |= dp[j - num];
    }
}
```

### 完全背包

```java
for (int coin : coins) {
    for (int j = coin; j <= amount; j++) {
        dp[j] = Math.min(dp[j], dp[j - coin] + 1);
    }
}
```

## 不变量

- 0/1 背包必须倒序
- 完全背包必须正序
- 状态必须足够表达历史选择影响
- 遍历顺序本身就是“是否允许重复使用”的一部分

## 容易误判

| 误判 | 实际结构 |
|---|---|
| Coin Change 当 BFS | 完全背包 |
| Target Sum 当 DFS | 背包DP |
| House Robber III 当普通DFS | 树形DP |

---

# 3）双序列匹配型状态

## 对应专题

- 序列DP

## 结构定义

两个序列共同推进。

典型状态：

```text
dp[i][j]
```

表示：

```text
A 前 i 个
B 前 j 个
```

之间的子问题。

这里的 `i,j` 不是网格坐标，而是两个序列各自处理到哪里。

## 结构信号

| 信号 | 可能结构 |
|---|---|
| 两个字符串比较 | 序列DP |
| 子序列匹配 | 序列DP |
| 编辑距离 | 序列DP |
| 公共子序列 | 序列DP |

## 代码骨架

```java
for (int i = 1; i <= m; i++) {
    for (int j = 1; j <= n; j++) {
        if (A.charAt(i - 1) == B.charAt(j - 1)) {
            dp[i][j] = dp[i - 1][j - 1] + 1;
        } else {
            dp[i][j] = Math.max(
                dp[i - 1][j],
                dp[i][j - 1]
            );
        }
    }
}
```

## 不变量

- `dp[i][j]` 必须对应明确子问题
- 字符访问通常是 `i - 1 / j - 1`
- 空前缀初始化必须明确
- 两个维度分别绑定两个不同序列

## 容易误判

| 误判 | 实际结构 |
|---|---|
| 子串当子序列 | 序列DP |
| 编辑距离当 BFS | 序列DP |
| 回文区间当 LCS | 区间DP |
| 看到 dp[i][j] 就按网格理解 | 状态维度误判 |

---

# 4）区间合并型状态

## 对应专题

- 区间DP

## 结构定义

小区间合并成大区间。

典型状态：

```text
dp[i][j]
```

表示：

```text
区间 [i,j]
```

的最优结果。

这里的两个维度是：

```text
左边界 × 右边界
```

## 结构信号

| 信号 | 可能结构 |
|---|---|
| 回文区间 | 区间DP |
| 戳气球 | 区间DP |
| 合并区间 | 区间DP |
| 石子游戏 | 区间DP |

## 代码骨架

```java
for (int len = 2; len <= n; len++) {
    for (int i = 0; i + len - 1 < n; i++) {
        int j = i + len - 1;

        for (int k = i; k < j; k++) {
            dp[i][j] = merge(...);
        }
    }
}
```

## 不变量

- 小区间必须先算
- 当前区间依赖更小区间
- 切分点必须完整枚举
- 遍历顺序通常按区间长度，而不是按普通行列

## 容易误判

| 误判 | 实际结构 |
|---|---|
| 回文子序列当双序列DP | 区间DP |
| 戳气球当贪心 | 区间DP |
| 石子游戏当 DFS | 区间DP |
| 看到 dp[i][j] 就按双序列理解 | 状态语义误判 |

---

# 5）树 / 图依赖型状态

## 对应专题

- 树形DP
- DAG DP
- 记忆化搜索

## 结构定义

状态依赖关系由树或图结构决定。

不是按下标推进。

而是：

```text
父节点依赖子节点
```

或：

```text
当前节点依赖邻居
```

## 结构信号

| 信号 | 可能结构 |
|---|---|
| 子树信息 | 树形DP |
| 树上路径 | 树DP |
| DAG 最长路 | 图DP |
| 重复 DFS 子问题 | 记忆化搜索 |

## 代码骨架

### 树形DP

```java
int[] dfs(TreeNode node) {
    int[] left = dfs(node.left);
    int[] right = dfs(node.right);

    return combine(left, right);
}
```

### 记忆化搜索

```java
int dfs(int i, int j) {
    if (visited[i][j]) {
        return memo[i][j];
    }

    visited[i][j] = true;
    memo[i][j] = ...;
    return memo[i][j];
}
```

注意：

> 不能简单用 `memo[i][j] != 0` 判断是否计算过，因为 0 可能本身就是合法答案。

## 不变量

- 子问题结果可缓存
- 图上 DP 必须保证依赖无环，或通过记忆化避免重复计算
- DFS 返回值语义必须稳定

## 容易误判

| 误判 | 实际结构 |
|---|---|
| DAG 问题当 BFS | 图DP |
| Longest Increasing Path 当回溯 | 记忆化搜索 |
| 树最大路径和当普通 DFS | 树形DP |

---

# ⑨ 空间压缩的统一理解

空间压缩不是一种新的 DP。

本质上是：

> 删除未来不会再被依赖的状态。

## 一维 DP

如果：

```text
dp[i] 只依赖 dp[i - 1]
```

则：

```text
O(n) → O(1)
```

如果：

```text
dp[i] 只依赖 dp[i - 1], dp[i - 2]
```

仍可压成常数空间。

## 二维 DP

如果：

```text
dp[i][j]
只依赖上一行 + 当前行已计算位置
```

则：

```text
O(mn) → O(n)
```

## 不能盲目压缩

如果后续仍需要完整历史状态，则不能直接删除。

判断标准不是：

```text
能不能少开数组
```

而是：

```text
未来还会不会依赖这个状态
```

---

# ⑩ 遍历顺序就是依赖关系的拓扑序

DP 的遍历顺序不是代码细节。

本质上是在保证：

> 每个状态被计算时，它的前驱已经完成。

例如：

### 线性 DP

```text
从左到右
```

### 网格 DP

```text
从上到下、从左到右
```

### 0/1 背包

```text
容量倒序
```

### 完全背包

```text
容量正序
```

### 区间 DP

```text
小区间 → 大区间
```

所以：

> DP 的遍历顺序，本质上是状态依赖图的一种合法拓扑序。

---

# ⑪ 与其他结构的边界

| 容易混淆 | DP结构 | 另一个结构 | 核心区别 |
|---|---|---|---|
| DP vs 前缀和 | 状态依赖 | 区间表达 | 前缀没有决策 |
| DP vs 贪心 | 保留多状态 | 局部选择 | 贪心要求局部选择可证明导向全局最优 |
| DP vs 回溯 | 合并子问题 | 枚举路径 | 回溯保留路径，DP 合并重复子问题 |
| DP vs BFS | 最优子结构 | 最短层数 | BFS 依赖层次扩展，不一定显式定义状态转移 |
| 线性DP vs 状态机DP | 阶段本身通常足够 | 阶段 + 状态身份 | 状态机需要额外记录历史身份 |
| 基础二维DP vs 序列DP | 二维有向推进 | 双序列匹配 | 两个维度语义不同 |
| 序列DP vs 区间DP | 双序列匹配 | 区间合并 | 状态依赖方向不同 |

---

# ⑫ 本章最容易犯的错误

- `dp` 状态含义不稳定
- 状态定义过于宽泛
- 初始化与状态定义冲突
- 遍历顺序错误
- 0/1 背包正序遍历
- 把二维数组误认为同一种 DP
- 把 `prev/cur` 当成状态定义，而不是空间优化
- 看到 `dp[i][j]` 就默认理解成网格坐标
- 状态机更新时错误使用当前轮已更新状态
- 只会背公式，不会解释状态意义
- 能贪心的问题强行 DP
- 把子串问题误判成子序列问题

---

# ⑬ 一维 DP 与二维 DP 的结构升级路径

从专题视角：

```text
线性 DP
↓
二维基础 DP
↓
背包 / 序列 / 状态机 / 区间 / 树形 DP
```

从结构视角：

```text
单轴状态推进
↓
二维有向推进
↓
状态开始承载更复杂的历史信息
```

真正的升级不是：

```text
一维数组 → 二维数组
```

而是：

```text
一个变量足够描述历史
→
需要两个变量共同描述历史
→
需要额外状态身份 / 区间 / 容量 / 树结构表达历史
```

---

# ⑭ 本章统一总结

DP 的真正核心不是：

```text
会不会写转移方程
```

而是：

```text
能否用状态正确表达历史影响
```

因此：

> DP 的本质是状态依赖结构。

真正的建模能力是：

- 知道哪些历史必须保留
- 知道状态最少需要几个变量描述
- 知道当前状态依赖谁
- 知道遍历顺序为什么正确
- 知道哪些历史以后不再需要，因此可以压缩

最后形成以下思维：

```text
状态语义
→ 状态依赖
→ 遍历顺序
→ 初始化
→ 最终答案
→ 空间优化
```

当你能从“状态依赖关系”而不是“数组长什么样”去理解 DP 时，才真正进入 DP 建模阶段。
