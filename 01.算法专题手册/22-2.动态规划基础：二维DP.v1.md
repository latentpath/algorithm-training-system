# 动态规划基础：二维 DP

## 本章目标

建立二维 DP 的基础建模能力：

> 当一个状态需要两个变量才能完整描述时，考虑 `dp[i][j]`。

本章重点不是“会写二维数组”，而是回答：

```text
i 表示什么？
j 表示什么？
dp[i][j] 整体表示什么？
当前状态来自哪些旧状态？
边界如何初始化？
```

---

# 一、二维 DP 的核心认识

二维 DP 不等于“二维网格题”。

`dp[i][j]` 只表示：

> 一个状态需要两个维度来描述。

常见含义包括：

```text
网格：
dp[row][col]

两个字符串：
dp[i][j] = 字符串 A 前 i 个字符与字符串 B 前 j 个字符的某种答案

区间：
dp[left][right]

物品 × 容量：
dp[i][j]

位置 × 状态：
dp[i][j]
```

所以看到二维 DP 时，不要默认把 `i, j` 当成坐标。

---

# 二、二维 DP 建模六问

遇到二维 DP，先问：

1. `i` 表示什么？
2. `j` 表示什么？
3. `dp[i][j]` 表示什么？
4. 到达当前状态的最后一步是什么？
5. 当前状态来自哪些旧状态？
6. 第一行、第一列或其他边界如何初始化？

网格 DP 是最适合练习这套思路的入门模型。

---

# 三、母题 1：LC62 Unique Paths

## 秒判关键词

二维网格、只能向右 / 向下、求路径数量。

## 状态定义

```text
dp[i][j] = 从左上角 (0,0) 到达 (i,j) 的路径数量
```

## 最后一步

到达 `(i,j)` 的最后一步只有两种：

- 从上方 `(i - 1, j)` 向下
- 从左方 `(i, j - 1)` 向右

所以：

```text
dp[i][j] = dp[i - 1][j] + dp[i][j - 1]
```

## 初始化

起点：

```text
dp[0][0] = 1
```

原因：

> 从起点到起点有 1 种方式：什么都不做。

第一行只能一路向右：

```text
dp[0][j] = 1
```

第一列只能一路向下：

```text
dp[i][0] = 1
```

## 标准代码：二维 DP

```java
public int uniquePaths(int m, int n) {
    int[][] dp = new int[m][n];

    dp[0][0] = 1;

    for (int col = 1; col < n; col++) {
        dp[0][col] = 1;
    }

    for (int row = 1; row < m; row++) {
        dp[row][0] = 1;
    }

    for (int row = 1; row < m; row++) {
        for (int col = 1; col < n; col++) {
            dp[row][col] =
                dp[row - 1][col] +
                dp[row][col - 1];
        }
    }

    return dp[m - 1][n - 1];
}
```

## 复杂度

```text
时间复杂度：O(m * n)
空间复杂度：O(m * n)
```

## 空间优化

因为当前行只依赖：

- 上一行同列
- 当前行左侧

可以压缩成一维数组：

```java
public int uniquePathsOptimized(int m, int n) {
    int[] dp = new int[n];

    for (int j = 0; j < n; j++) {
        dp[j] = 1;
    }

    for (int i = 1; i < m; i++) {
        for (int j = 1; j < n; j++) {
            dp[j] = dp[j] + dp[j - 1];
        }
    }

    return dp[n - 1];
}
```

学习阶段优先掌握二维版本。

# 四、母题 2：LC63 Unique Paths II

## 秒判关键词

路径计数 + 障碍物。

## 状态定义

和 LC62 完全相同：

```text
dp[i][j] = 从 (0,0) 到达 (i,j) 的路径数量
```

障碍物并没有改变“我们要求什么”，所以状态定义不需要改变。

## 状态转移

如果当前格子是障碍物：

```text
dp[i][j] = 0
```

如果当前格不是障碍物：

```text
dp[i][j] =
    dp[i - 1][j] +
    dp[i][j - 1]
```

## 初始化难点

第一行和第一列不能像 LC62 一样全部初始化为 1。

例如：

```text
S  .  X  .
```

则：

```text
1  1  0  0
```

原因：

> 第一行只有一条前进路线，一旦被障碍物截断，后面的格子虽然不是障碍物，也无法到达。

因此：

> 第一行 / 第一列一旦遇到障碍物，后续位置保持 0。

## 标准代码

```java
public int uniquePathsWithObstacles(int[][] obstacleGrid) {
    int row = obstacleGrid.length;
    int col = obstacleGrid[0].length;

    int[][] dp = new int[row][col];

    for (int j = 0;
         j < col && obstacleGrid[0][j] != 1;
         j++) {
        dp[0][j] = 1;
    }

    for (int i = 0;
         i < row && obstacleGrid[i][0] != 1;
         i++) {
        dp[i][0] = 1;
    }

    for (int i = 1; i < row; i++) {
        for (int j = 1; j < col; j++) {
            if (obstacleGrid[i][j] != 1) {
                dp[i][j] =
                    dp[i - 1][j] +
                    dp[i][j - 1];
            }
        }
    }

    return dp[row - 1][col - 1];
}
```

## 关于起点 / 终点特判

起点或终点是障碍物时，答案必然是 0。

可以显式提前返回：

```java
if (obstacleGrid[0][0] == 1 ||
    obstacleGrid[row - 1][col - 1] == 1) {
    return 0;
}
```

但不是必须。

如果初始化和状态转移写得正确，答案也可以自然得到 0。

这里更准确的术语是：

> 边界特判 / 提前返回

而不是搜索算法中的“剪枝”。

# 五、母题 3：LC64 Minimum Path Sum

## 秒判关键词

二维网格、只能向右 / 向下、求最小路径和。

## 状态定义

```text
dp[i][j] =
从 (0,0) 到达 (i,j) 的最小路径和
```

注意必须明确写出：

> 最小

因为这个限定直接决定转移使用 `min`。

## 最后一步

到达 `(i,j)` 仍然只有两个来源：

- 上方 `(i - 1, j)`
- 左方 `(i, j - 1)`

但这次不是统计两边的方案数，而是选较小的路径和：

```text
dp[i][j] =
min(dp[i - 1][j], dp[i][j - 1])
+ grid[i][j]
```

## 初始化

起点：

```text
dp[0][0] = grid[0][0]
```

第一列只能从上往下：

```text
dp[i][0] =
dp[i - 1][0] + grid[i][0]
```

第一行只能从左往右：

```text
dp[0][j] =
dp[0][j - 1] + grid[0][j]
```

## 标准代码

```java
public int minPathSum(int[][] grid) {
    int row = grid.length;
    int col = grid[0].length;

    int[][] dp = new int[row][col];

    dp[0][0] = grid[0][0];

    for (int i = 1; i < row; i++) {
        dp[i][0] =
            dp[i - 1][0] + grid[i][0];
    }

    for (int j = 1; j < col; j++) {
        dp[0][j] =
            dp[0][j - 1] + grid[0][j];
    }

    for (int i = 1; i < row; i++) {
        for (int j = 1; j < col; j++) {
            dp[i][j] =
                Math.min(
                    dp[i - 1][j],
                    dp[i][j - 1]
                )
                + grid[i][j];
        }
    }

    return dp[row - 1][col - 1];
}
```

## 复杂度

```text
时间复杂度：O(row * col)
空间复杂度：O(row * col)
```

# 六、三个母题的统一骨架

LC62、LC63、LC64 的前驱结构完全相同：

```text
        上
        ↓
      当前 ← 左
```

也就是：

```text
(i - 1, j)
(i, j - 1)
```

真正变化的是：

> 如何组合前驱状态。

### LC62

路径数量：

```text
上 + 左
```

### LC63

障碍物：

```text
障碍物 → 0
否则 → 上 + 左
```

### LC64

最小路径和：

```text
min(上, 左) + 当前代价
```

所以不要把它们记成三套独立模板。

应该记成：

> **状态相同，前驱相同，聚合方式不同。**

# 七、迁移题：最大金币路径

如果题目变成：

> 每个格子有金币，只能向右 / 向下，求从左上角到右下角最多获得多少金币。

状态定义：

```text
dp[i][j] =
从 (0,0) 到达 (i,j) 能获得的最大金币数
```

状态转移：

```text
dp[i][j] =
max(dp[i - 1][j], dp[i][j - 1])
+ grid[i][j]
```

第一行、第一列仍然做累加。

它和 LC64 的 DP 结构没有本质区别：

```text
LC64：min
最大金币：max
```

这说明：

> 真正应该学习的是状态结构，而不是题号。

# 八、二维 DP 与线性 DP 的关系

线性 DP：

```text
dp[i]
```

一个主要变量足以描述状态。

二维 DP：

```text
dp[i][j]
```

需要两个变量才能完整描述状态。

例如：

### 一维

```text
dp[i] =
以 i 结尾的最大连续子数组和
```

### 二维网格

```text
dp[i][j] =
到达网格位置 (i,j) 的答案
```

### 两个字符串

```text
dp[i][j] =
字符串 A 前 i 个字符与
字符串 B 前 j 个字符之间的答案
```

因此：

> 二维 DP 的本质不是“矩阵”，而是“状态有两个维度”。

---

# 九、从网格 DP 过渡到序列 DP

以后遇到 LCS：

```text
dp[i][j]
```

不要再把 `i,j` 理解成网格坐标。

例如可以定义：

```text
dp[i][j] =
字符串 s 的前 i 个字符
与字符串 t 的前 j 个字符
的最长公共子序列长度
```

这里：

```text
i = s 处理到哪里
j = t 处理到哪里
```

这正是二维 DP 从“具体坐标”走向“抽象状态”的关键一步。

# 十、常见坑点

| 坑点 | 正确反应 |
|---|---|
| 看到 `dp[i][j]` 就认为是二维网格 | 先问 i、j 分别代表什么 |
| 状态定义缺少“最大 / 最小 / 数量”等限定 | 把状态定义写完整 |
| 起点机械初始化为 0 | 初始化必须服从状态定义 |
| 第一行 / 第一列照抄模板 | 根据“是否可达”重新分析 |
| 障碍物只考虑内部转移 | 障碍物通常也影响边界初始化 |
| 直接空间压缩 | 先写完整二维表 |
| 只记公式，不知道从哪里来 | 从“最后一步”反推前驱状态 |

# 十一、二维 DP 面试速记

看到二维 DP 时，依次说：

```text
1. i 表示什么？
2. j 表示什么？
3. dp[i][j] 表示什么？
4. 当前状态最后一步来自哪里？
5. 转移公式是什么？
6. 边界如何初始化？
7. 最终答案在哪里？
8. 是否可以空间压缩？
```

一句话：

> **先定义两个维度，再寻找状态之间的方向关系。**
